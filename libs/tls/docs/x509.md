# Lane 3: x509 (DER, PEM, certificates, chain validation, private keys)

Code in `src/tls/x509/`: `der.mojo` (strict reader), `pem.mojo`, `cert.mojo` (`Certificate.parse`), `chain.mojo`
(`verify_chain`, `host_matches`, `load_system_roots`), `sigs.mojo` (`verify_sig`), `key.mojo` (`load_private_key`).
`shim/` is a temporary MIT port of Mosaad-M/tls SHA-2, bigint, RSA and ECDSA verify; only `sigs.mojo` and `key.mojo`
import it. At integration replace those imports with `tls.sym` / `tls.asym` and delete `shim/`.

## What verify_chain enforces
- Chain input leaf first, at most 10 certificates, any order of intermediates; the root may be present or absent.
- Path found by names, structural rules run, then signatures verify top-down from the trusted root (a key the peer
  supplied is used only after the root vouched for it). At most 16 signature attempts per call.
- Validity at the caller's `now` (inclusive), unknown critical extensions, duplicate extensions, signature algorithm
  equal inside and outside the TBS, cA and keyCertSign agreement, pathLen (self-issued intermediates not counted),
  intermediate EKU, leaf serverAuth and digitalSignature, DNS and IP name constraints (self-issued intermediates
  skipped, wildcard SANs checked against the excluded subtrees they cover), name types it cannot check fail closed.
- Refused: SHA-1 signatures, RSA issuer keys below 2048 bits, RSA-PSS with a hash/MGF1 mismatch, leaf keys that are
  not P-256, P-384 or RSA >= 2048 (the suites of docs/plan.md cannot use them).
- Hostname: SAN only (RFC 9525), never the CN. IP literals match iPAddress only. Wildcard: whole left-most label,
  at least two labels after it. One trailing dot on the host is ignored.
- Trust anchors: extensions of the anchor itself are not processed except cA/keyCertSign/pathLen/name constraints; a
  v1 root without basicConstraints is accepted.

## Known differences from other verifiers (all in tests/data/divergences.txt or tests/limbo_known.txt)
- openssl: see the reasons in `tests/data/divergences.txt` (15 cases).
- x509-limbo: 57 of 9748 cases differ. Ours too lenient (pedantic profile checks real clients skip): SKI/AKI presence,
  serial number rules, CN-in-SAN, public-suffix wildcards, AIA contents, NC extension in an end entity, unknown
  critical extension or missing basicConstraints in the root itself. Ours too strict (policy): a CA certificate in
  leaf position without digitalSignature, ML-DSA keys, more than 10 certificates offered (8 BetterTLS path-building cases).
