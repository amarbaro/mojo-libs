# imkit memopt: 7.9 MB less for an app without glass, 9 bugs fixed, 1 us slower per frame

An app that composes with `render_into` into its own buffer held 13.5 MB at `Layer` creation; it now holds 5.6 MB.
Nine bugs surfaced in `src/imkit`, each with a test that failed first and its own commit. The compose kernel is
unchanged, and the UI frame costs about 0.9 us more because `push` now refuses NaN. I could not prove the kernel's
time to better than about 2%, for a reason given under Speed.

Branch `lane-memopt`, base v0.8.0 (`b21eb3a`), rebased onto main `732b335`. 15 commits, no push. Sonnet, high effort.
Measured with `tools/membench` (bytes, mallocs, compose) and `tools/uibench` (CPU frame), both committed; baseline
binaries built from `b21eb3a`.

## The card and the pinned buffer held three buffers nobody read

Demo frame, 1280 x 720, no glass.

| item | before | after | commit |
|---|---|---|---|
| `Layer.scene` (device) | 3,686,400 B at creation | 0 B until the first `set_scene` | `9434c66` |
| `Layer.pixels` (pinned host) | 3,686,400 B at creation | 0 B until the first `readback()` or `render()` | `16c3986` |
| `Font.atlas` (host) | 524,288 B | 65,536 B (rows in use, steps of 64; a CJK glyph adds 32 KB) | `d8b13b4` |
| host heap, Draw + Font | 761,988 B | 237,236 B | |
| device buffers | 9,069,636 B | 5,383,236 B (+ 3,686,400 B once `set_scene` runs) | |

Total footprint, `render_into` into the app's own buffer: 13.5 MB (device 9.07, pinned 3.69, host 0.76) to 5.6 MB.
Through SDL with `render()` the pinned buffer returns on frame 1: 13.5 MB to 9.3 MB.

Correction: the `9434c66` body says the device total went "9.57 MB to 5.89 MB". That was an addition error; the sums
above are of the buffers `membench` prints.

Measured and left alone:
- Host allocations: build + finish of the demo frame makes 0 malloc calls (`Theme.copy` is a stack copy). `render_into`
  makes 12 (3.8 KB) and `render` 17 (5.0 KB), inside the runtime's `create_sub_buffer`. Under 2% of the call.
- `Draw.cmd` 128 KB and `bins` 64 KB are fixed worst cases, 4% of the footprint; making them growable puts a capacity
  check into `push`. Left.
- `Assets` load and `pack` allocate per pixel: once at start, and an offline tool. Left.
- Binary: `examples/gallery` 397,128 B to 401,624 B (+1.1%, the new checks); `quickstart` 87,480 B both.

## The kernel did not change; its time is unproven to 2%

| measure | before | after |
|---|---|---|
| compose per launch, `membench` median of 5 x 1000, quiet box, alternating | 16.9, 17.1, 17.2 us | 17.4, 17.5, 17.4 us |
| compose per launch, `ui_test` | 21.28 us (gate 0) | 21.32 us (gate 13) |
| source of `compose`, `rrect`, `srect`, `glass`, `backdrop`, `blur_down` | | byte-identical to `b21eb3a` |
| UI frame, `uibench`, 8 alternating rounds | median 20.5 us, min 17.4 | median 21.4 us, min 20.5 |

`membench` reads +0.3 us on compose. The code did not move, so it is buffer placement or GPU state, and I could not
separate them: other lanes held the machine at load 30 to 50 and queued 2 h GPU jobs, and a bisect across commits would
have measured them. "Compose must not get slower" is met in source and unproven in time below about 2%.
`render_into` and `render` read 134 and 348 us in gate 13 against 61 and 209 us in gate 0, again load; the
alternating `membench` runs give 71 to 80 and 203 to 216 us for both builds.

The frame's +0.9 us (+4%, 1.4% of `render_into`) is the price of `push` testing for NaN and clamping four coordinates per
command. A scalar form of the same guard measured 20.5 to 21.7 us, so the vector form stayed.

## Nine bugs, each failing before its fix

| bug | failing test | fix |
|---|---|---|
| `clip(A); clip(B); unclip()` left A in tiles only A covered, cutting a later rect there | `clip_at` walks a tile's bin like the kernel | `e9f22df` |
| `Ui.glass`, `Ui.icon_img` ignored `Ui.scale` | DPI 1.5 cases, 3 failed | `4d9e547` |
| `Ui.field` Backspace removed a byte (invalid UTF-8); the tail scan could start inside a sequence | Backspace on "a, e-acute, CJK" failed. The tail case cannot show in pixels with Roboto (U+FFFD is as wide as its letters), so `cp_floor` and `cp_ceil` are tested directly | `696025b` |
| `png_decode`: IHDR length unchecked; a 4 G x 4 G header asked for 96 GiB and aborted | edited bytes of `rgba.png`; IHDR and 20000 x 20000 failed, 4 G crashed | `20b7084` |
| NaN and infinite coordinates: a -inf..inf rect landed in tile 0 only (`Int()` of an infinity), NaN in an arbitrary tile | full-layer rect missing from every tile but 0 | `6284716`, vector form `7cbbe52` |
| `set_assets` and `set_image` both wrote pool offset 0 and erased each other | `ui_test`: no raise, picture erased | `781e172` |
| a font size index past the font's sizes read out of range (`text`, `tw`, `asc`) | crashed | `def3b03` |
| `Font.ext` key `codepoint << 4 \| slot`: slot 16 returned slot 0's glyph | 17-size font, width 6 at slot 16, 13 expected | `2b95130` |
| `scroll_begin` row height 0, negative or NaN returned `end = INT64_MIN`; `num` printed garbage for NaN and for 1e9 and up | both failed | `45204fe` |

Probed, no bug: `slider` with width 0; NCMD and NBIN overflow (counted, `finish` stays inside NBIN); atlas full
(`font.full` counts); `fit()` cuts on code points; DPI rounding in `Ui.text`; `Assets` with negative offset or size
(`Draw.image` rejects and counts).

Noted, not fixed: the image pool offset is a Float32, exact below 2^24, so `-DUI_IMG=` above 16.7 M pixels would address
wrongly; `menu_item` ids start at `0x100000` and can collide with an app's ids; PNG CRCs are unchecked.

## API changes, all additive or caller-compatible

- `Layer.set_image(px, w, h, off = 0)`: optional pool offset. It and `set_assets` now raise instead of overwriting each
  other. `image_fits` takes `off`.
- `Layer.set_assets`, `set_scene`, `readback`, `render` take `mut self` (they allocate or record state). A caller holding
  `var layer` is unchanged; one holding it immutably no longer compiles. `blur_from` keeps `self`, so
  `layer.blur_from(layer.scene)` still compiles.
- `Layer.scene` is empty until `set_scene`; `Layer.pixels` is empty until the first `readback()` or `render()`.
- New names: `Font.has_size`, `ui.cp_floor`, `ui.cp_ceil`, `draw.sane`, `draw.BIG`, `assets.MAXPX`.
- Behaviour: NaN commands drop and count; coordinates clamp to +-1e6; a bad font size draws nothing (counted);
  `Draw.clip` emits one more command when it replaces a clip; `png_decode` refuses over 64 M pixels; `Font` raises past
  256 sizes; `scroll_begin` reads a bad row height as 1; `num` prints `nan`, `>1e9`, `<-1e9`.
- No other signature changed, no new feature.
