# Rules

`what broke -> the rule`

- `String(span_of_bytes)` printed `[65, 98]` -> build a String from bytes with `String(unsafe_from_utf8=span)`, never `String(span)`.
- `var f: T = default` in a `@fieldwise_init` struct did not parse (Mojo 1.2) -> to add a defaulted field, write the `__init__` by hand and keep the old positional order.
- A test of `Layer` needs a GPU, and `ui_cpu_test` runs without one -> put pure checks (`image_fits`) in a function the CPU test calls, the GPU path goes in `ui_test`.
- `scripts/mutants.sh` sed pattern stopped matching after a fix reworded the line it breaks ("sed changed nothing") -> a mutant's sed must be checked against the current source whenever that line changes; run `scripts/mutants.sh` in the same gate as the change.
- `out` as a parameter name did not parse (`expected argument name`) -> `out` is a keyword in Mojo 1.2; name it `buf`.
- A scripted source edit (python `str.replace`) matched nothing and the CLIP branch of compose never landed; the CPU tests passed and only the GPU pixel test caught it -> every scripted edit asserts its anchor is found (`assert old in s`), and a compose branch is not done until a GPU pixel test drew it.
- `fb.g[i]` formed in the same expression as a call that appends to `fb.g` was rejected (`use of invalidated interior reference`) -> call the mutating method on its own line, then read.
- `render_into(mut self, ..., buf = self.img)` was rejected as aliasing -> a method that only reads `self` takes `self` immutably.
- A failed `mojo build` leaves the old binary, and the test then "passed" -> `rm` the binary before building, or read the build's exit status; never trust a PASS from a binary newer than its source.
- Lane A's new `Ui` forwarders ignored `Ui.scale` -> every `Ui` method that takes a position, size, radius, border, glow or offset multiplies by `self.scale`; a new one gets a DPI 1.5 check in `ui_cpu_test`.
- A pixel-equality check between two spots of a translucent glass panel failed because the backdrop gradient differs -> compare neighbours with a tolerance, or against a colour that cannot be the backdrop, and prove the check fails with the feature removed.
- Neon's cyan accent under light text was 1.2 : 1 -> a fill colour needs its own text role (`on_accent`), and every preset's pairs are contrast-tested (WCAG 4.5 text, 3 graphics).

- Merging lane B onto lane A broke the build: A made `Font.width` mutating (on-demand glyphs) and B's `tw`/`fit` called it from `self` -> after a merge, build every target (`scripts/ci.sh`) before any test; a method that becomes `mut` is an API change, list it in the lane report.
- Both lanes brought a `glass` into one test (draw's shader, theme's preset) -> new public names get a grep across `src tests examples` before the commit; on a clash import one under an alias (`glass as tglass`).
- `window_test` failed under `gpu-wait` with `SDL_Init failed`: the queue starts jobs in a clean env -> a GPU job script for SDL tests exports WAYLAND_DISPLAY, DISPLAY, XDG_RUNTIME_DIR, HOME and PATH.
- Removing the lane worktrees deleted their ignored `.work/` reports and gate receipts -> lane reports are tracked files (`docs/reports/`); the `worktree` gate in iTools protocol_gates refuses the removal otherwise.
- A web-model code draft (DeepSeek RRECT) called a nonexistent `x.bits()`, changed the widget API and wrote colours in the wrong byte order -> a model draft is input, not code: compile it, test it, and check its colours against `rgba()` before use.
- The boss's wavewait-style regex habit: a kernel name searched as written in source matched nothing -> match Mojo GPU kernels by name prefix; the compiled symbol carries a mangled suffix.
- `Draw.clip` replacing a clip without `unclip` left the old clip in tiles only it covered, so a later rect was cut there -> a command that changes GPU-side state per tile ends the old state first; the CPU test walks a tile's bin as the kernel does (`clip_at`).
- The malloc-count shim reported 0 allocations for a UI frame because Mojo's `List` and `String` allocate through `KGEN_CompilerRT_AlignedAlloc`, not libc `malloc` -> a counter that reads 0 is checked against a call that must allocate before it is trusted; wrap the runtime allocator too.
- `scripts/ci.sh` runs `uv sync`, which rewrote `uv.lock` and showed up as a modified file -> `git checkout uv.lock` after each gate, and commit by explicit path, never `git add -A`.
- `Ui.glass` and `Ui.icon_img` forwarded their coordinates unscaled, so they sat wrong at DPI 1.5 although the rule above already named this class -> the rule was not enforced by a check; `ui_cpu_test` now has a DPI 1.5 case for every `Ui` forwarder that takes a position, and a new forwarder is not done until it has one.
- The `icon_img ignores its size` mutant's sed stopped matching when the DPI fix reworded its line, and the gate failed on it -> the rule above held: re-aim every mutant at lines a change touches in the same commit, and run the whole gate before committing, not after.
- `Ui.field` Backspace removed one byte, so an app's "é" or "中" became invalid UTF-8, and the tail scan stepped one byte so it could start inside a sequence -> text edits and cuts go through `cp_floor` / `cp_ceil`, never `byte_length() - 1` or `s += 1`.
- My first "stray glyph" test for the field tail passed before the fix: Roboto's U+FFFD (13 px) is as wide as its letters, so the stray start never wins the width scan -> a test for a fix must be seen to fail first; when the symptom cannot be reached with the test font, test the helper that carries the rule and say so in the report.
- A test took `.as_bytes()` of a temporary `String`, a dangling view that happened to pass -> bind the String to a `var` before viewing its bytes.
- `png_decode` trusted the IHDR length and the picture size: a 4 G wide header asked for a 96 GiB buffer and aborted, a short IHDR read bytes of the next chunk -> a decoder checks every length and bounds every size-driven allocation before it allocates, and its bad-input fixtures are edited bytes of a good file (`error_of`), one per field. A sizes product is checked per side first, because two 32-bit sides overflow Int64.
- The first draft of the 20000 x 20000 test would have allocated 1.6 GB before it failed -> a red run that can allocate is sized so the machine survives it (here 20000 x 20000, not 100000 x 100000).
- `rect(-inf, -inf, inf, inf)` was binned into tile 0 only and a NaN rect into an arbitrary tile, because `Int(Float32)` of an infinity or NaN is undefined -> no `Int(float)` on a value the caller supplied before it is clamped; `Draw.push` drops NaN (counted) and clamps coordinates to +-1e6, and `span` clamps its pad.
- `Draw.dropped` is cumulative across frames, so my first NaN test compared it to an absolute 4 and failed for the wrong reason -> a test of a counter reads it before and after.
- `set_assets` and `set_image` both wrote pool offset 0, so whichever ran second silently erased the other's pictures, and the old ui_test passed because it never drew the first picture again -> two writers of one buffer region track what they own and raise on overlap; `set_image` gained `off` (additive) so both can live. A test that loads A then B draws A again.
- I ran a bare `git stash` to "get a clean tree" in a worktree whose stash stack is shared with other sessions -> never `git stash` here; commit a WIP, or `stash push -u -m <tag>` and `apply` by SHA. (Only my entry was on the stack, and it was restored.)
- Timing of the UI frame swung 18 to 160 us because other lanes held the machine at load 50, and valgrind aborts on Mojo binaries -> on a loaded box compare the minimum of many short rounds of old and new binaries run alternately (`tools/uibench.mojo`), not one wall-clock number, and say the load in the report.
- `Layer.render` and `readback` are `mut self` now that `pixels` is allocated lazily; a method that may allocate a field cannot take `self` immutably -> allocate-on-first-use fields force `mut self`, so check each caller (`examples/gallery`) builds in the same commit (`scripts/ci.sh` builds them all).
- `Ui.text(.., size=3)` on a three-size Font read past `ascent` and crashed (an index is input too) -> every public method taking a font size slot checks `Font.has_size` first and counts a drop; a Mojo `List` index is not bounds-checked in a release build.
- The `Font.ext` cache key was `codepoint << 4 | size slot`: for slot 16 the OR lands on a set bit, so slot 16 returned slot 0's glyph (6 px at size 26) and nothing failed -> a packed key reserves a field for the whole range its index can take (256 slots here, checked in `Font.__init__`); a width in the key's range limit gets a test at the first value past it.
- Rewording the `Font.ext` key broke the `glyph cache ignores the size` mutant's sed, and I committed before running the whole gate; the gate caught it -> the rule above, again: a commit that touches a line named in `scripts/mutants.sh` (`grep` the old text there) updates the mutant in the same commit.
- `scroll_begin(.., rh=0)` returned `end = INT64_MIN` and `num(nan)` printed `1.-9079256848778919936`, both `Int(float)` of a value the caller supplied -> the `Int(float)` rule above covers the widgets too: any widget that floors or rounds a caller's float guards it first, and a probe script (`.work/dbg`) tries 0, negative, NaN, inf and 1e30 on each before the test is written.
- My first fix renamed `scroll_begin`'s parameters to avoid shadowing, which would break keyword callers (`rows=`, `rh=`) -> never rename a public parameter to fix a local; use a local name (`rl`, `nr`).
- A SIMD self-compare `v.ne(v)` was folded to false, so NaN commands were not dropped, while the scalar `x != x` worked -> use `isnan` for a NaN test; the NaN test in ui_cpu_test caught it the same minute, so a guard keeps its test when it is rewritten for speed.
- Under load the same base binary read 17.3 and 20.4 us in one session -> compare 8 alternating rounds and give the median and the min of both, not one pair.
- A stale mutant sed failed a 25-minute gate three times (reworded line each time), and the written rule did not stop it -> it is a gate now: `scripts/ci.sh` runs `MUTANT_DRY=1 scripts/mutants.sh`, which checks in under a second that every sed still changes its file; a commit that rewords a mutated line fails in the first minute.

- A merge commit written with `git merge -m` carried a model attribution line; the selftag gate checks `git commit` only. -> Merge messages follow the commit rules: no attribution, check `git log -1 --format=%B` after every merge.
