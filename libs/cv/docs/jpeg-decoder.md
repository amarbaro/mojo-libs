# Baseline JPEG decoder

`jpegio.load_jpeg` decodes stock JPEGs to an interleaved BGR `Mat[DType.uint8]`.
It handles 8-bit SOF0 with Huffman coding, grayscale or three components,
4:4:4, 4:2:2, 4:2:0, separate or interleaved sequential scans, and DRI/RST
restart markers. The output uses the ISLOW integer IDCT, fancy chroma
upsampling, and fixed-point YCbCr conversion.

The parser validates segment lengths, Huffman tables, scan coverage, and the
restart sequence. It rejects a truncated entropy stream or missing EOI.
It returns an `unsupported:` error for other coding processes, sampling,
component counts, rotated EXIF, and profiles outside the stock loader's sRGB
check. The sRGB check uses the profile text and accepts single-segment ICC
profiles. The decoder limits frames to 64 Mi pixels, as imkit does.
`jpegio.load_jpeg` adds the `jpeg-fallback:` prefix, so
`scripts/mcv-stockcheck` retries that image through its existing external
decoder. TurboJPEG is a test oracle.

## Implementation

The hot path is Huffman decoding and dequantization of each block. The bit
reader takes four unstuffed bytes at a time and has a marker-aware slow path.
A 10-bit lookup resolves common symbols and their signed magnitudes in one
step. Each block is transformed immediately into padded sample planes, so
separate scans can fill their planes with a single block of coefficient
scratch space. SIMD runs eight IDCT vectors and eight output pixels at a
time. The IJG integer butterfly and chroma weights use the in-tree imkit
decoder as their reference. That decoder combines scalar, progressive, and
pixel-packing code internally. Reusing it through its exported API would
add a library dependency and an intermediate RGB buffer.

## Gates

Run from the CV directory. The planted JPEG directory is generated by
`tests/stock_planted.sh`. Use the original 406-image manifest and the
`4e99c700`-era stock JSONL for the final gate.

```sh
tests/jpeg_baseline.sh "$PLANTED_JPEG_DIR"
JPEG_CPU=6 tests/jpeg_speed.sh "$BENCHMARK_JPEG"
tests/jpeg_stock.sh "$STOCK_LIST" "$STOCK_TURBO_JSONL"
```

| Gate | Result |
| --- | --- |
| Pixel parity | 42 fixtures, maximum absolute difference 0 against TurboJPEG ISLOW |
| Unsupported inputs | 7 variants took the unsupported path |
| Corrupt inputs | 37 truncation and garbage cases raised within the 20 s per-file limit |
| Speed on one Ryzen 7 7800X3D core | 55.61 ms Mojo, 54.20 ms TurboJPEG, 1.03× (limit 1.20×) |
| Peak RSS for one decode | 108,120 KiB Mojo, 77,888 KiB TurboJPEG |
| Planted stock CLI cases | Plain, rotated, CMYK and scRGB JPEG results match ImageMagick |
| Stock CLI | `mcv-stockcheck -j 14`, 406 image results and 12 duplicate pairs, byte-identical JSONL |

The benchmark uses the first 6144 × 3456 JPEG in the original eight-image
bench list (SHA-256
`9b6c032f36e7b1b534347b097d707b3a5731986cba7e2554f053c90cf6a8cc08`).
Both decoders read the same preloaded bytes. The speed gate alternates
decoder order and takes nine timings per decoder after warm-up. Peak RSS
comes from separate one-decode processes. The padded 4:2:0 sample planes
account for approximately 30 MiB of the Mojo process's peak RSS.
