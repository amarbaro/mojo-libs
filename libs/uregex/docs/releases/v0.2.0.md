# mojo-uregex v0.2.0

**Released:** 2026-10-07 · **Commit:** `5e8e875` · **Previous:** first release

## What it does

Unicode-aware regular expressions for Mojo, built for LLM pre-tokenizers (GPT-2,
Qwen, Llama 3, DeepSeek, Spark) and checked against Python's `regex` by
differential testing. Pure Mojo, CPU, build with `-I src`. mojo-baro's tokenizer
uses a vendored copy (`uregex/`).

## Highlights

- 2.0 to 3.2x faster than Python `regex` on the tokenizer patterns (0.1.0 ran at 0.55 to 0.83x).
- Compiled patterns are 6x smaller (166 KB to 27.6 KB each).
- New syntax in `FullPattern`: capture and named groups, `\b` `\B`, fixed-length lookbehind; lazy quantifiers in both engines.
- Case-insensitive matching covers the Unicode 17 case pairs Python's `regex` uses.

## Changes

### Added
- `FullPattern`: capture groups, `(?P<name>...)` / `(?<name>...)`, `\b` `\B`, `(?<=...)` `(?<!...)` (fixed length); `findall_groups`, `groups()`, `group_index(name)`.
- Lazy quantifiers `*? +? ?? {m,n}?` in `Pattern` and `FullPattern`.
- `findall_spans` (byte spans), `findall_cps_offsets` (codepoint spans).
- `recipe.yaml` (rattler-build) and `pixi.toml` tasks `test`, `gate`, `bench`, `package`.
- `tools/bench_compile.mojo`; `difftest.py --bytes`; the gate runs both offset modes and builds every tool.
### Changed
- **Offsets are UTF-8 byte offsets.** `search` and `Match` now report bytes; use `findall_cps_offsets` for codepoints. `findall`, `split_keep` and `findall_cps` are unchanged for callers.
- Matching runs on the UTF-8 bytes directly (no codepoint list, no per-match string rebuild).
- One-shot helpers (`findall`, `search`, `split_keep`, `compile`) accept the full syntax.
### Fixed
- `(?i:...)` missed the 26 case pairs new in Unicode 17.0 (e.g. U+16EA0/U+16EBB, U+A7CE/U+A7CF): case maps now come from `regex` itself.

## Known limits

- Backtracking engine: pathological patterns can be exponential.
- No backreferences, possessive quantifiers or variable-length lookbehind.
- `FullPattern` is slower than `Pattern` for the same pattern; use `Pattern` unless you need its syntax.
- gpt2-style patterns run about 5% slower than just before step 6 (still 2.2x Python).
- Positions are Int32 internally: inputs over 2 GiB are not supported.

## Upgrade / run

```
# offsets: Match.start/end from search() are now bytes
var m = search(r"\p{N}+", "一二三42").value()     # 9, 11 (was 3, 5)
Pattern(src).findall_cps_offsets(text)             # codepoint offsets
FullPattern(r"(\w+)").findall_groups(text)        # groups need FullPattern
```
