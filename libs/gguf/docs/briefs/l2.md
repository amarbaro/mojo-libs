# L2: latent data baked into a GGUF (haiku lane, branch `lane-l2`)

Read `common.md` first.

Our latent method needs per-model latent data next to the weights: the LatentMAS realignment W_a (d x d), the hidden
to embedding scale beta, the median token_embd row norm. llama.cpp rejects unknown tensors ("wrong number of tensors",
`src/llama-model-loader.cpp:1391`) but ignores unknown KV, so the data goes in as KV and the file stays loadable.

Deliver `src/gguf_latent.mojo` with two commands, built on the merged U1 reader/writer:
- `gguf-latent bake IN OUT --wa W.f32 --beta B --row-median M`: copies IN (KV order kept, tensors streamed, never
  loaded whole) and appends `latent.version` (u32 1), `latent.beta` (f32), `latent.embd_row_median` (f32),
  `latent.w_a` (array of f32, row-major d*d from W.f32), `latent.w_a.shape` (array of u32, [d, d]). Baking a file
  that already carries latent.* replaces those keys (same bytes as baking the clean file).
- `gguf-latent show FILE` prints exactly `latent beta B median M w_a DxD`.

Fixture: `.work/oracle/latent/qwen-wa.{f32,txt}` (latent-wa on qwen2.5-0.5B; beta and median are read from the txt).

Gate: `tests/l2-gate.sh` must print `PASS 7/7` and exit 0; the llama.cpp load check queues a CPU-only llama-cli under
gpu-wait (it may wait for the GPU queue; it does not use the GPU).
