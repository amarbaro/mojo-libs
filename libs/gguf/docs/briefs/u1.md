## Deliverable

| file | what |
|---|---|
| `src/gguf/` (package, files your choice) | GGUF v3 little-endian reader and writer |
| `src/gguf_rewrite.mojo` | CLI |
| `exchange/lane-u1-<lane>-report.md` | report (below) |

CLI: `gguf-rewrite IN OUT [--name STR] [--remove KEY]...`

- Parses IN into an in-memory model: header, every KV in file order with its typed value (all 13 GGUF value
  types, arrays of strings, nested arrays), every tensor info (name, dims, type, offset), alignment
  (`general.alignment` or 32), and the data offset.
- Serializes OUT from that model. Tensor data is streamed from IN (mmap or chunked reads), never held whole.
- First stdout line, exactly: `kv K tensors T alignment A data_offset D` for IN (K = the header's KV count,
  D = byte offset where IN's tensor data starts).
- `--name STR` sets `general.name`; `--remove KEY` drops that KV. Result must be byte-identical to
  `gguf_new_metadata.py --general-name STR --remove-metadata KEY` on the same input: read that script for
  where a replaced key lands and how offsets and padding are recomputed.
- With no edit flags, OUT is byte-identical to IN.
