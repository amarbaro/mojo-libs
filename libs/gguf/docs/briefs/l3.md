# L3: latent quality metric (sonnet lane, branch `lane-l3`; L1 follows in this lane)

Read `common.md` first.

llama.cpp judges a quant by perplexity. Our latent method needs to know whether a quant keeps the geometry latent
steps read: the final-norm hidden, the soft embedding, the W_a map. Build the metric; L1 (per-tensor precision search
scored by it) follows in this lane once this gate is green.

Deliver `src/latent_metric.mojo` -> `latent-metric REF.gguf TEST.gguf PROMPTS.txt OUT.json`, one row per prompt (its
last position). JSON keys (numbers): `prompts`, `cos_mean`, `cos_min` (final-norm hidden cos), `top1_agree` (logit
argmax equal), `soft_cos_mean`, `soft_cos_min` (cos of softmax(logits) . token_embd, each model with its own
token_embd, dequantized by the merged U6 `src/gguf/dequant.mojo`), `wa_recovery` (TEST's W_a known-answer probe: of
256 fixed tokens t = (k*977+13) % vocab, the share whose W_out[t] W_a has nearest token_embd row t by cosine; W_a =
(W_out^T W_out + lambda I)^-1 W_out^T W_in with lambda = 1e-4 trace/d, see `~/iTools/llm/latent-wa/latent-wa.mojo`).
Forward passes: `hidden-probe-dump MODEL PROMPTS OUT` (llama.cpp CPU, dumps result_norm and result_output per prompt,
790 MB per 32 prompts on 0.5B: delete your dumps after reading them). Everything after the dump is ours, deterministic
(same inputs, same JSON bytes).

Reference numbers from the gate's own oracle (`tests/l3-cos.py` on qwen2.5-0.5B, 32 prompts): cos_mean bf16 vs bf16
1.0, vs Q4_K 0.982794, vs Q2_K 0.868768.

Gate: `tests/l3-gate.sh` must print `PASS 8/8` and exit 0.
