# U2: table generator (haiku lane, branch `lane-u2`)

Read `common.md` first.

Goal: the gguf-py tables our converters need, generated into Mojo from the pinned Python, never hand-ported.

Deliver:
- `tools/gen-tables.py GGUFPY_DIR OUT_DIR`: imports gguf-py from GGUFPY_DIR, writes `OUT_DIR/consts.mojo` and
  `OUT_DIR/tensor_map.mojo`. Deterministic (same input, same bytes).
- The generated files committed as `src/gguf/consts.mojo` and `src/gguf/tensor_map.mojo` (exactly the generator's output).
- `src/u2_dump.mojo`: prints ONE line of compact JSON with sorted keys, exactly what `tests/u2-oracle.py` prints,
  built only from the generated Mojo tables (read u2-oracle.py: value_types, quant_types, quant_sizes, arch_names,
  tensor_names, arch_tensors, keys, name_map for llama/qwen2/qwen35/qwen35moe/qwen4exp at n_blocks=2).
- A lookup the converter will call: `map_tensor_name(arch: String, n_blocks: Int, hf_name: String) -> String`
  (empty when unmapped), plus the enum values as Mojo constants.

Sources: `gguf-py/gguf/constants.py`, `gguf-py/gguf/tensor_mapping.py`.

Gate: `tests/u2-gate.sh` must print `PASS 7/7` and exit 0.
